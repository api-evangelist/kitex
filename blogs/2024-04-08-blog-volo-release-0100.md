<p>In Volo 0.10.0, we mainly focused on extensibility and ease of use.</p>
<h2 id="break-change">Break Change</h2>
<h3 id="error-handling-refactored">Error Handling Refactored</h3>
<p>Existing error types had issues such as unclear semantics, lack of maintainability and extensibility, and misuse. In the new version, we refactored the entire error handling, greatly enhancing the clarity and maintainability of error handling, and reducing misuse through the type system.</p>

<p>For middleware that is not aware of user errors, this change should not cause a breaking change. If you are aware of user errors, then just change the original <code>volo_thrift::Error</code> to <code>volo_thrift::ServerError/ClientError</code>.</p>
<h5 id="client-migration">Client Migration</h5>
<p>The error part of the client has changed from <code>ResponseError</code> to <code>ClientError</code>. Just follow the compiler error message prompts to match the new error variant.</p>
<h3 id="idl-management-file-voloyml-format-refactored">IDL Management File volo.yml Format Refactored</h3>
<p>The structure of the new yml configuration is clearer, easier to maintain, and mainly solves the issue that the old version could not support cross-repository referencing with git. The specific functions and configuration parameters can be seen <a href="https://www.cloudwego.io/docs/volo/guide/config">here</a>. In addition, for the volo-cli command-line tool, we have renamed the previous idl command to repo.</p>
<h4 id="migration-guide-1">Migration Guide</h4>
<p>Install the volo-cli v0.10.0 version and execute the volo migrate command in the volo.yml directory for automatic migration.</p>
<h3 id="change-in-default-generated-enum-type">Change in Default Generated Enum Type</h3>
<p>In the newly generated code, the default generated Enum type has been changed to a newtype wrapping i32, in order to better support forward compatibility of modifications in the enumeration values of the IDL enum field.</p>
<h4 id="migration-guide-2">Migration Guide</h4>
<p>Just modify the enumeration name in the enum field to the corresponding generated name, such as <code>Foo::Bar</code> -&gt; <code>Foo::BAR</code>.</p>
